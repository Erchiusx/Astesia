# Tool-based interaction

The default worker now uses ordinary text responses and task-scoped MCP tools. New private deployments initialize with `speech_tool_enabled`, `reuse_conversation_sessions` and `persist_interactive_sessions` enabled. Existing deployments must deliberately enable these flags and replace the old protocol-oriented private instructions with the new prompt template.

## Boundaries

- Persona and standing/task instructions are passed through Codex `developer_instructions`, not concatenated into the user prompt. Built-in Codex system instructions remain intact. The user message contains the current request and relevant data.
- `speak(text)` enqueues a speech message and returns after the broker commits it. TTS, transport, retries and deadlines belong to application code. `queued` does not mean heard. The model may immediately keep working and call speak again later. Neither commentary nor the final text is implicitly spoken, and completion does not generate a duplicate voice message.
- Memory is the existing local versioned SQLite database. `memory_search`, `memory_read`, `memory_upsert`, and `memory_forget` let the agent query and maintain it on demand. The adapter handles versions, receipts, backups and evidence validation. Background tasks cannot mutate memory. No complete memory index or prior-message listing is injected into the user prompt.
- `conversation_search(query)` explicitly searches a bounded number of prior turns in the current broker conversation. Historical dialogue and durable memory remain different stores.
- Interactive requests resume the same Codex session for each broker conversation, rather than repeatedly constructing a synthetic chat transcript. A new conversation starts a separate session; background briefings remain ephemeral. Old per-task sessions are not silently replayed into a new tool-mode conversation.

The private prompt remains editable as `assistant-instructions.txt`. A worker restart is needed for configuration changes; prompt content is read each task. Tool context and credentials live outside the agent's writable workspace. The local stdio server exposes only narrow operations; its configured approval policy permits these authorized tools without enabling unrelated MCP servers or broadening the shell sandbox.

## Compatibility and validation

The broker retains its older completion format for existing workers. A tool-mode worker sends ordinary final text in an internal transport envelope; that envelope is constructed by code, not requested from the model. Existing voice delivery consumes the added speech message kind; explicit speech receives no automatic greeting.

The extraction was tested with Codex CLI 0.167.0: a real Codex turn called the stdio speech tool against a local stub broker, then completed further computation; a second request resumed the same session. Saved rollout records placed the test persona in the developer role, not the user role. Offline tests cover lease validation, enqueue-before-completion, retry deduplication, explicit repeat calls, no duplicate final audio, routine deadlines, memory evidence/idempotence, scoped history lookup and no injected history/persona. No live phone audio was generated by the stub integration test.

Reference: [Codex MCP configuration](https://learn.chatgpt.com/docs/extend/mcp) and [developer instructions configuration](https://learn.chatgpt.com/docs/config-file/config-reference).

## Terminal concurrency

A saved thread permits one active writer. A terminal resumed through the shared background daemon may retain that ownership briefly after the client leaves. The worker therefore runs with `--no-daemon`, uses `data/session-access.lock` around interactive execution, and waits for terminal access to finish.

The worker retries a thread-store writer conflict only when its event stream shows no turn or tool execution began. Errors after execution begins are never automatically replayed by this conflict handler. Normal request deadlines still apply. This avoids both immediate generic failures on handoff and duplicate mutations.
